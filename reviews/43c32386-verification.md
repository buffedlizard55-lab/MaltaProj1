## Conditional additional research for unresolved matches

The landing reads the existing `reread/data/source_check.csv` format receipts. It does **not** treat the verifier's VRS `match` label alone as proof of the point value: code review found that some anchored VRS receipts validate rank/name, not the claimed points. Numeric points are instead independently retrieved from the **immutable official Valve file through GitHub's API**, parsed and matched by exact name. Duplicate team labels, ambiguous aliases, changed point values or failed source reads all suppress the fallback.

Only matches unresolved by the primary route enter this ladder. Fresh successful HLTV format receipts (BO1/BO3/BO5), exact confirmed historical rating points for both teams, standings <=14 days old, a fresh fixture capture and a future lock are required. Formula: `p=1/(1+10^((Rb-Ra)/400))`; BO3 `p²(3−2p)`; BO5 `p³(10−15p+6p²)`. The scale and independent-map assumptions are project choices, **uncalibrated**, not Valve or HLTV forecasts. These outputs are labelled **Research pick / Provisional model**, never confirmed bookmaker probabilities.

At the fixed 04:00 UTC test time, these strict conditions yield 5 primary picks + 8 provisional research picks + 15 unresolved among 28 fixtures. Counts vary with source reads, locks, new fixtures and receipt age. Missing inputs stay blank; the linked existing every-match board retains broader, separately flagged research.
