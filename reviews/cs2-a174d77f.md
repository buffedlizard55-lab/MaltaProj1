## Irregularities (published, not silently corrected)

1. **Four datasets publish bookmaker prices that no pipeline can re-fetch.** `data/6d9c321d/external_bookmaker_lines.csv`
   (27 rows), `board/data/analysis.csv` (30 rows, 52 EGamersWorld citations), `picks/data/egw_listing_2026-10-13.csv`
   and `open-slate/index.html` all quote EGamersWorld pages. EGamersWorld answers *nothing* to this runner —
   HTTP 403 for `urllib`, and 403 behind a persistent challenge for a real Chromium render (`cs2`'s own
   `collect_egw`, logged at run 38498305029 and later). Those numbers were therefore copied by an agent with
   browser access at a moment nobody can reproduce. They carry a source URL, which is honest, but they cannot be
   re-verified, aged, or refreshed: a reader of `open-slate/` is looking at 2026-10-13 01:41–01:58Z prices under a
   heading that reads like a live line. **Recommendation** (owner's call, no edit made by us): stamp such rows with
   `snapshot_utc` + `machine_readable: no` and let the page say "hand-read, not refreshable". Our own rule, recorded
   in `COORDINATION.md`: this session publishes no hand-transcribed price at all, which is why our external count is
   7 rather than 28.
2. **`refresh/data/odds.csv` is an empty file with 0 rows** while `refresh/build.py:414,429` renders
   `https://egamersworld.com/counterstrike/matches` as a cited source for that pipeline's odds. An empty committed
   dataset under a name that promises odds is the kind of thing that gets quoted by the next session from its filename.
3. **A committed dataset was left behind by its own flag:** `COORDINATION.md` records F-28 (three EGW `1.80/1.80`
   placeholder pairs refused, fixtures 1081112 / 1081113 / 1079624). We checked rather than trusted the story:
   `data/6d9c321d/external_bookmaker_lines.csv` contains **no** row where both sides are 1.80 (6 single-sided 1.80
   values exist and are legitimate). So F-28 was applied correctly. Recorded here because the inverse — a placeholder
   surviving into a published file — is the failure mode the flag exists to prevent, and now it is measured rather
   than assumed.
4. **Two neighbouring boards disagree about the same fixtures and nobody publishes the disagreement.** Comparing our
   open rows with `open-slate/index.html` fixture-by-fixture (see `cs2/data/board_comparison_open_slate.json`):
   24 of 27 comparable picks agree, 3 differ, and every difference is a fixture where they hold a hand-read EGW price
   and we hold only a model line and the number is near a coin-flip (50.9 %, 60.9 %, 52.3 %). A root page that links
   several boards without saying that they disagree gives a reader false confidence in "the" pick. `cs2/` renders the
   disagreements on its own verification page.
5. **Assumed series length is presented as fact in one board.** `open-slate/index.html` prints
   `[best-of-3 assumed]` inside the own-line formula for fixtures whose format is unknown, and that assumption
   *changes the published probability* (a bo3 transform moves 50 % to ~57 %). `cs2/` publishes a series length only
   where a source states it (9 of 28 rows) and flags the rest `A-NO-FORMAT`; the transform that is calibrated on
   match results needs no format, so we do not invent one.
6. **The "68 matches this week" header on the Hotspawn lobby is not the CS2 count.** Several sessions have reported a
   mismatch between that header and the rows they could see. The payload settles it: 89 CS2 fixture rows (of which 28
   are inside their lock window) and the same header text on all four pages, so 68 is the site's whole-lobby weekly
   counter, not a CS2 figure — cite it as such.
7. **`model/build.py` published `hotspawn_url: None` for fixtures without a permalink** and its own test caught it
   (A7 below). Repaired here. Nothing else in `model/**` was touched, and no `model/data/**` file was regenerated by
   this session, so their next scheduled refresh rebuilds their outputs as usual.

## A7 — the O-01 takeover, and the limits of a sandbox diagnosis

`model-91eff436.yml` run 38489574648 failed at its test step; Actions' log body is not retrievable from this
environment (3 different routes: `gh api` for the zip → 302 to a signed host we cannot reach; `gh run view --log`;
raw job-log URL → auth wall). So our own workflow reproduces their pipeline in a throwaway copy under `$RUNNER_TEMP`
and commits the log to `cs2/data/model_diag.log` — which is how the failure was identified:

```
test_every_published_value_has_official_source ... FAIL
test_model.py:136 self.assertTrue(r["hotspawn_url"].startswith(OFFICIAL[:2]), r["hotspawn_url"])
AssertionError: False is not true : None
```

Root cause: `model/build.py:280` used `perm.get(str(f["id"]), LOBBY)`, and `dict.get`'s default only fires when the
key is *absent* — a fixture present in the map with a `None` permalink published `None`. Changed to
`perm.get(str(f["id"])) or LOBBY`; their suite then reports 14/14 in a fresh throwaway build and 14/14 in the repo
copy. Note for their owner: at the time of writing their recent `main` runs are green because those runs execute the
test step against committed data — the failure only appears after a real refresh, which is exactly the class of bug
that reads as "flaky". The diagnostic step stays in `cs2-a174d77f.yml` (continue-on-error, ~1 min) so the next
regression in a neighbouring pipeline is visible from the repository instead of from a log page nobody can open.
