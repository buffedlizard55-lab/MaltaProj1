How every number on this site is produced

  • Fixture list (complete, not sampled). The five public Pick'em pages are fetched by an Actions job (src/pickem_inventory.py, run 38445027513). Each page embeds its full data set in <script id="ng-state">; the parser reads that payload and writes one row per match with the payload's own id, competition, tier, offered points, stage, status, exact UTC scheduled_start_time and lock_time, both participants and the board's crowd percentages. Rendered-card counts are recorded as a cross-check (27 / 26 / 231 cards vs 86 / 85 / 294 payload rows).
  • External lines. Prices are read from off-site bookmaker pages (EGamersWorld's BC.Game price widgets and its match lists). Each row keeps the source URL and the UTC capture time; two readings are kept where a market moved. Nothing is typed from memory and no price is inferred from a ranking, a crowd percentage or a model.
  • Our own line. For every fixture with a real two-way price the margin is removed: p(A) = (1/odds_A) / (1/odds_A + 1/odds_B), and the residual 1/odds_A + 1/odds_B is shown as the overround. This de-vigged probability is the project's own line and is labeled as such on every page.
  • What is deliberately blank. Where no public price exists the odds and probability cells are empty and the fixture is listed on the Flagged page. Hotspawn's crowd percentage appears in its own column, tagged as metadata, and is never an input.
  • Reproduce. python src/pickem_inventory.py (needs internet; runs in CI) → python pipeline/build_site.py → this site plus lines/analysis.csv.

Reading the tables

  • priced — real two-way bookmaker price; own de-vigged probability published.
  • no real line — the only thing the source shows is its generic 1.8/1.8 default.
  • blank / unverified — no public price found; intentionally empty.
  • live / finished — the payload's own status; picks for those matches are closed.
