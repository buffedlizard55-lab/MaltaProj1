Methodology

Data sources — in priority order

  1. Polymarket CS2 markets — real-money prediction market. Decentralized and transparent, with the most liquid esports markets. Used as the primary line when available.
  2. HLTV.org match pages — show a "Betting" widget with aggregate odds from multiple bookmakers and HLTV's own VRS (Valve Regional Standings) simulation. Used to cross-check and to confirm match metadata.
  3. EGamersWorld (EGW) — aggregator showing bookmaker odds across multiple CS2 titles, plus map-balance stats.
  4. vprognoze.ru / stavka.tv / Marathonbet / Betcity / Melbet lines — used as secondary cross-checks.

We do NOT use Hotspawn's public pick percentages (the "% picked" numbers on play.hotspawn.com) when computing probabilities. Those are crowd picks, not market odds, and we have observed them to be heavily skewed by name recognition (e.g., fnatic at 90% when bookmakers price the match ~50/50). We display them in a separate column only so you can see where the public disagrees with the market — that is often where pick'em value exists.

Probability derivation

For each match with posted decimal odds (a, b):

  1. Compute raw implied probabilities: p̂a = 1/a, p̂b = 1/b.
  2. Remove the overround (bookmaker margin): normalize so probabilities sum to 100%: 
    P(a) = (1/a) / (1/a + 1/b)
P(b) = (1/b) / (1/a + 1/b)
  3. This gives the "fair" (margin-removed) implied probability displayed in the table.

For Polymarket, prices are already near-fair (small overround ~1-3% because it's a binary CDA market), but we still normalize to 100% for consistency.

What we do NOT do

  • We do not invent odds. If a verifiable external line could not be confirmed for a match, the probability cells are left blank and the row is marked Unverified and surfaced on the Flagged for Review page.
  • We do not infer odds from team names, rankings, or past results. Rankings are mentioned in notes for context only.
  • We do not average conflicting odds arbitrarily. Where sources disagree materially (≥10 percentage points), we pick the highest-liquidity source (usually Polymarket) and flag the discrepancy on the Flagged page.

Verification process

  1. Match metadata (date, teams, tournament, tier) verified against Hotspawn lobby page.
  2. Each match with odds has a Source link column pointing to the public page the odds were taken from.
  3. Cross-checked HLTV event pages exist for S-tier and Stake Pulse Beat III matches.
  4. Where HLTV aggregate odds materially differ from Polymarket at capture time, the row is flagged as "partial" verification.
  5. Rows marked "Verified" have odds from at least two sources in the same direction within ~5pp.

Tiers (Hotspawn definitions)

  • S — 7 base points, ×3 multiplier. Top-tier LAN events (Thunderpick World Championship 2026).
  • B — 3 base points, ×1.5 multiplier. Mid-tier events (Stake Pulse Beat III, CCT, ESL Challenger regional cups).
  • C — 2 base points, no multiplier. Smaller online cups (Elisa BreakOut Series, etc.).

Points multiplier (×1.25) is applied per weekly Hotspawn configuration.

Known limitations

  • The Hotspawn lobby is a React SPA; the full 86-match list is loaded client-side. Our static scraper sees only the ~26 server-rendered matches in "Closing Soon" / "Upcoming". Rows for the rest are not fabricated; this coverage gap is called out on the Flagged page.
  • LoL tab was not rendered in the static HTML fetch; LoL matches are not yet in the data.
  • Odds move. Probabilities shown are snapshots at the time of page generation; the gen-time timestamp is shown on the dashboard.
  • BO1 matches (Elisa BreakOut groups) are more volatile and have thinner markets than BO3s.
