Method & sources

This board exists to answer the brief's question for every Counter-Strike 2 fixture on Hotspawn, including the low-tier matches that bookmakers do not cover. It is built automatically: a GitHub Actions job reads the public pages, rebuilds the pages and the CSV data, and fails without publishing if any check does not hold.

How a probability is chosen (in this order)

  1. Bookmaker line — an exact-match whole-match moneyline from Pinnacle's public guest response (American prices converted to decimal), or from EGamersWorld's aggregated two-way decimal pair on the match page. De-vigged: p_A = (1/odds_A) / (1/odds_A + 1/odds_B). The overround is printed on the row.
  2. Prediction market — Polymarket, only when the market names both teams and a start time within 120 minutes of the fixture. Published as the implied probability, labelled, never de-vigged and never averaged with a bookmaker price.
  3. Our own line — originated from official rating files only: Valve Regional Standings points with the official 400-point logistic, or, when either team is missing there, the official HLTV world ranking with a rank logistic (100 rank positions per 90% per-map favourite, the repository's documented default). The per-map figure is converted to the series length only when Hotspawn states one (BO3 → 0.5748 at pmap=0.55, for example); otherwise the row says “per-map” and is flagged MP-F05.
  4. Blank. If none of the above is available, no probability and no pick are published; the row goes to the Unresolved page.

What Hotspawn is and is not used for

Used: fixture identity, competition, tier, stage, offered points, exact UTC start and lock epochs, and the score published for a finished fixture. Not used: the crowd pick percentages in the same payload. The collector drops every crowd field at ingest and this page reports how many were dropped (1437 in the capture shown here); the build fails if a crowd value appears in the dataset.

Verification rules

  • Every published row carries a source link and the UTC time the source was read.
  • If a value cannot be confirmed from an official or clearly-labelled source it is left blank and flagged — never inferred, never interpolated.
  • A fixture the payload lists without participant names is published as an unresolved row rather than dropped, so a coverage gap can never be invisible.
  • The score of a finished fixture is cross-checked against the repository's independently verified result trail (HLTV match pages read by an earlier session); a mismatch is flagged MP-F30 and both values are shown.
  • Unit tests recompute every published probability from the stored inputs and compare it to the generated page, so a page can never disagree with its own data.

Refresh cadence

The workflow runs every 4 hours (and on demand). Each run re-reads Hotspawn, the rating files, the bookmaker sources and the prediction market; the data files and pages are regenerated together, so the timestamp on a row always belongs to the numbers next to it.
