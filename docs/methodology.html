Reverse-engineering (what the lobby actually is)

  • play.hotspawn.com/lobby server-renders a first page of fixtures (26 CS2 fixtures extracted verbatim with Hotspawn match IDs 1079438–1081076) plus filter facets claiming 86 total (85 CS2 + LoL), “60 matches this week”, reset in ~5d 06h at fetch time.
  • Each card exposes: start time (timezone not stated — F-10), tournament, points/tier/stage/multiplier, a hotspawn.com/matches/… link, and crowd pick %. The rest of the 85 is loaded client-side; pairings beyond the 26 were not guessed.
  • CS2 facet counts sum exactly to 85 (see inventory). No authenticated/API scraping was attempted; no manual input is required to re-run: re-fetch the two lobby URLs, diff data/matches.csv, re-run scripts/model.py.

Originating OUR OWN lines (the only probabilities we publish as “ours”)

Inputs: only HLTV world ranks recorded in data/ratings.csv, each with its source URL. Formula (Elo logistic, fully reproducible in scripts/model.py):

rating = 2000 − 300·log10(rank)  ·  P(A beats B) = 1/(1+10^(−(ratingA−ratingB)/400))  ·  fair decimal odds = 1/P.

Worked, checkable examples: FURIA #4 vs BETBOOM #13 → 70.8% (fair 1.41); 9z #17 vs Aurora #6 → Aurora 68.6%; Legacy #6 vs PARIVISION #11 → 61.2%; MIBR #18 vs BC.Game #52 → 68.9%; HOTU #42 vs fnatic #40 → 49.1%.

Limitations (stated, not hidden): rank-only — ignores maps, veto, form, roster changes and LAN/online. Where either rank is unverified the cell is blank. External bookmaker match-win odds, where they exist behind bookmaker pages, could not be verified numerically and are blank; outrights are never presented as match lines. Implied probability = 1/decimal; no-vig = raw ÷ sum of raws.

Update procedure (no manual input)

  1. Re-fetch lobby + CS2 lobby; add new fixtures to data/matches.csv with Hotspawn URLs.
  2. Refresh ranks in data/ratings.csv from the dated HLTV ranking page; keep old snapshots flagged.
  3. Run python3 scripts/model.py; rebuild pages; any row still missing a rank stays blank on Flagged.
