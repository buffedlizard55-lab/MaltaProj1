Method, sources & read times

1. Fixture list (Hotspawn)

Hotspawn Play is an Angular app that ships its data in the page as <script id="ng-state">. The collector reads all three CS2 surfaces and takes, per fixture: id, tournament, tier, stage, points breakdown, teams, scheduled_start_time and lock_time (epoch ms), plus the crowd pick share (kept as "ownership").

2. Probability ladder

  1. Pinnacle whole-match moneyline from the public guest JSON behind pinnacle.com CS2; American prices → decimal; margin removed proportionally (p = (1/o) / Σ(1/o)).
  2. Polymarket match-winner markets (tag "counter strike 2"), mid prices normalised to 100%. A prediction market, labelled as such.
  3. Our own line: P(A) = 1 / (1 + 10^(−k·ΔPoints/400)) with Valve's official points (standings 2026-10-05). k = 0.4598 (fitted on Valve's published match results); trained on 13609 Valve-rated matches, held out on 901 (window 2026-09-07..2026-10-05): log-loss 0.6395 vs 0.6541 for Valve's raw curve; Brier 0.2234 vs 0.2237.
  4. Unresolved: blank pick, flagged, listed on the Unresolved page with the research trail.

Joins require both teams to match after verified aliases (aliases.json) and a kickoff within 6 h; any gap is flagged. HLTV ranks are shown as a cross-check (HLTV ranking, status observed).

3. Leaderboard plan

See Leaderboard plan; thresholds live in model.py. Situational factors come from research/notes.json (HLTV links, read times, strength) plus an automatic "new five" check on Valve's per-team match tables.

4. Automation

GitHub Actions workflow runs every 3 hours (inside the 4–8 h requirement even if a scheduled run is dropped): collect → calibrate → model → build → tests; pages are committed only when the tests pass, otherwise the last good pages stay up and the failure is visible in the run log.
